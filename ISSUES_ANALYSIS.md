# Issues Analysis

## 1. Elements Analysis Missing Data

**Problem**: AI says "Without specific element counts" even though data is passed

**Root Cause**: The compact prompts work, but the AI isn't properly reading the `equilibrium` object from the request

**Backend Request Structure** (correct):
```json
{
  "question": "...",
  "hexagram": { ... },
  "equilibrium": {
    "elements": { "wood": 20, "fire": 40, ... },
    "missing": ["earth"],
    "strongest": "fire",
    "weakest": "earth"
  }
}
```

**AI Prompt** (working):
```
TECHNICAL DATA (JSON) - THIS SECTION
{"elementCounts": {"wood": 20, "fire": 40, ...}, ...}
```

The data IS there. The AI might need explicit instruction to use `elementCounts`.

## 3. Interpretation Not Translated (Showing English in ES tab)

**Problem**: AI interpretation only in English, Spanish tab shows English text

**Root Cause**: Multiple issues:

### A. Field Name Mismatch
**Backend returns**:
```json
{
  "core-analysis": {
    "technicalAnalysis": "...",
    "colloquialInterpretation": "..."
  }
}
```

**TranslationService expects**:
```json
{
  "analysis": {
    "coreTechnical": "...",
    "coreColloquial": "..."
  }
}
```

The field names don't match!

### B. Missing Translation Call
Logs show:
```
[TranslationService] Cache hit for 2026-02-28T14:29:24.970Z (es)
[TranslationService] Applied coreColloquial to both fields for es, length: 0
```

`length: 0` means cached translation is empty.

### C. SECTION_CONFIG Field Mismatch
```javascript
// translation-service.js line 29
analysis: {
    fields: ['coreTechnical', 'coreColloquial', 'analysis', 'symbolism']
}
```

But backend returns `colloquialInterpretation` not `coreColloquial`.

## Fixes Needed

### Fix 1: Elements - Explicit AI Instruction
Update `generateElementsAnalysis` system prompt to explicitly say:
```
Analyze these element counts: ${JSON.stringify(elementCounts)}
```

### Fix 2: Remedies - Defensive Coding
In `handleRemediesSelect`, check if instructions exist:
```javascript
const authInst = entry.structure?.instructions || entry.instructions || "No instructions available";
```

### Fix 3: Translation - Field Name Mapping
Two options:

**Option A**: Backend returns expected field names
Change backend to return `coreColloquial` instead of `colloquialInterpretation`

**Option B**: TranslationService maps field names
Add field name mapping in SECTION_CONFIG

### Fix 4: Force Translation on Load
Currently cache returns empty translations. Should:
1. Check if translation is empty
2. If empty, re-translate
3. Don't cache empty results

## Quick Wins

1. **Remove empty cache entries** when translation fails
2. **Add field aliases** in TranslationService
3. **Log what fields are actually present** in the interpretation
